# ZHOOR AIOS agent instructions

## Identity

This is the canonical repository for **ZHOOR AIOS**. Its former HERMES-AIOS GitHub identity was renamed in place to ZHOOR-AIOS. Do not implement the legacy broad AIOS roadmap unless a current ZHOOR job explicitly adopts an item.

## Rules

1. **Repository evidence is truth.** Record durable decisions, tests, and handoffs here; do not rely on chat-only state.
2. **Use the ZHOOR board.** Work only on an owner-assigned `READY` job card. The orchestrator alone updates `WORK_BOARD.md`.
3. **One bounded session.** Read only card-listed context, obey its write scope, validate, write a unique handoff, and stop.
4. **Route skills minimally.** Use `skill-router`; load the mandatory `karpathy-guidelines`; do not load unrelated skills/workflows.
5. **Deterministic first.** No model/backend dependency before the benchmark gate; no model output authorizes execution.
6. **Stop after two failures.** Record evidence and ask the owner instead of looping or weakening checks.
7. **Parallel safety.** Concurrent agents require isolated worktrees and disjoint write sets. Do not communicate with other agents directly.
8. **Approval safety.** Routine reversible project-local work may be auto-approved. Destructive, network, package-install, credential, push/merge/release, architecture, grilling, and final-review actions require explicit approval.
9. **Git safety.** Never discard unknown changes. Commit or push only when the owner explicitly assigns it; use one logical conventional commit.
10. **Security boundary.** Recommendation, authorization, and execution remain separate. Initial workers have no autonomous effect.
